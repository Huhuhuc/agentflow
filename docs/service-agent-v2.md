# AgentFlow 售后工作台：本轮交付与操作

本轮按既定顺序落地多轮会话、资料入库、工单审核、独立执行，以及服务端评测管理和交付检查。默认使用Mock，没有配置或调用付费模型。

## 现在如何打开

正常使用：双击项目根目录 start-agentflow.bat，打开 http://127.0.0.1:5173。后端启动时进行版本化增量建表升级，保留已有数据。默认演示账号沿用原项目设置。

页面验收环境使用独立的 backend/ui-review.db；它与正常启动使用的 agentflow.db 分开。验收期间创建的会话与实验只存在于该演示数据库。不要将验收记录当作生产记录。

首次进入新工作台，点击「加载明确标注的演示数据」，为当前租户初始化A101/A102/A103及两条政策；重复点击不会覆盖已导入订单和政策。新工作台不再直接用Python常量作为业务数据源。

## 三分钟完整演示

1. 在「会话与工单」输入“我要申请退款”，选择Mock，新建会话。状态变为等待补充。
2. 在同一任务中回复“A102”。观察订单事实和政策依据。
3. 继续回复“请生成工单，说明商品存在质量问题”。
4. 修改标题和处理说明，先「保存草稿修改」，再「确认并创建工单」。
5. 填写处理记录，标记处理中或记录解决结果。刷新页面、重启服务后仍可查到会话和工单。
6. 展开引用、轨迹和审核记录，检查政策版本、审核人及修改前后内容。

会话、业务任务和每次运行分别存储，补充消息会创建新的执行尝试并沿用已确认的订单/主题。消息历史最多保留40轮，模型请求使用最近8轮历史。当前一次任务处理一个订单；多个不同订单号会要求澄清。

重复创建任务和重复发送消息使用客户端幂等键，旧任务版本的写入会返回409。新消息会替代未确认草稿；已确认的工单需要另建任务继续提出新申请。

## 导入订单

进入「订单与政策」，选择CSV文件或粘贴文本。必填id/status/amount；已签收订单还需要days_since_delivery/used，运输中订单需要overdue：

    id,status,amount,days_since_delivery,used,overdue
    A201,delivered,199,3,false,
    A202,shipping,89,,,true

当前订单号格式为A加三位数字，状态支持delivered/shipping，布尔字段为true/false。最多1000行。整份文件验证成功后才提交；任何一行有误都不部分导入。同一订单号更新本租户记录，不影响其他租户。

## 政策与证据

导入Markdown/TXT，填写文档标识、标题、适用范围及可选生效时间。相同标识发布新版本，不覆盖原正文。当前支持退款/已签收与配送/运输中两类政策。

运行选择当时已生效的最高版本；最高有效版本下线时撤回该文档，不自动恢复旧版。尚未到生效时间的新版本不影响当前任务。

正文按段落和800字符块切分，保留段落号、块内位置、文档ID和版本。检索为主题筛选加字符bigram排序，最多返回5块，是明确的词法基线，尚未采用向量检索。长文本Mock汇总会截断，不能据此声称自动解释了全部政策。

每次运行把可用订单和政策版本保存为快照。确认工单时重新核对订单内容和被引用政策块；订单更新、政策改版或下线会拒绝旧草稿。此时发送“请按最新资料重新核对”，审核新的结果。人工修改的说明也保存在审计记录中。

## 工单与权限

本轮提交的工单为平台内可查询、可更新的持久化记录，包含open/in_progress/resolved状态。解决工单必须填写处理记录。尚未接入外部工单供应商。

admin/staff可以导入资料、编辑审核草稿、更新工单和维护实验；viewer可查看所属租户的记录并发起任务，但不能审批或管理资料。所有查询和操作按租户过滤。旧business确认接口拒绝新会话运行，避免绕过版本校验和审计。

## 独立Worker

本地默认EXECUTION_MODE=inline。企业任务仍保留原租约、检查点、过期回收和旧worker防写入。配置EXECUTION_MODE=celery后，API只提交任务，独立worker执行：

    celery -A app.worker.celery_app worker --loglevel=INFO --pool=solo -Q celery,business,evaluation

Docker Compose已配置PostgreSQL/Redis/API/worker/web，以及模型配置向worker传递。worker并发可通过部署参数调整。数据库保存调度尝试记录；broker故障时任务保持pending，扫描器至少间隔30秒重试派发。重复投递仍须通过数据库原子领取，租约期限150秒，单个运行ID最多领取三次。

这保证本地任务/工单去重，不承诺模型请求exactly-once。HTTP请求已经发出后取消不能退回供应商费用；进程在响应到达与检查点提交之间退出时可能重放未保存轮次。

## 服务端评测管理

「评测与复核」可载入标准数据集、运行Mock开发集/测试集、查看结果、保存逐条事实评分、比较实验和下载完整JSON。导入自定义数据集使用JSON：

    {"name":"我的回归集","cases":[{"id":"dev-01","split":"dev","category":"refund","text":"A101退款条件是什么","action":"answer","order":"A101","policy":"refund-v1","fact":"可申请但不保证成功"}]}

数据集最多24例，每组最多12例，ID不得重复。实验复制数据集，历史实验不会随新数据集改变。分组、重复次数、模型、代码哈希、数据集哈希和完整轨迹保存在报告中。人工评分有审核人、时间和版本；并发评分拒绝覆盖旧版本。

此评测当前面向独立的标准工具运行器，使用固定合成订单/政策，不读取租户资料库，不代表新会话流程的端到端模型成功率。会话、资料更新及审批流程由集成测试覆盖。自动契约通过与事实正确率分别计算，尚未完成人工复核时事实正确率为空。

真实模型实验可通过 /api/v1/service/experiments 显式创建mode=openai；未配置密钥会拒绝。当前页面只提供Mock实验按钮。真实评测仍须另行配置和实测。

实验可取消；失去执行器或超时的实验会明确失败，不自动重放付费评测。队列派发失败也明确报错。需要再次实验时主动创建新的实验。

## 数据库升级、CI和登录

app.migrations提供001_core、002_service两个版本化增量建表步骤，并在schema_versions登记。新库和已有旧库均可升级，重复升级保持幂等；已有表缺少必要字段时拒绝自动登记。当前迁移只涉及新增表，未来字段变更必须编写新的迁移操作，不会自动修改旧列。

    .\.venv\Scripts\python.exe -m app.migrations

GitHub Actions配置后端回归、前端构建，以及PostgreSQL服务下的数据库升级/并发领取检查。CI尚未推送或实际运行；本机无Docker/PostgreSQL，对应本地测试跳过。

/health/live检查进程，/health/ready检查数据库和Celery模式下的Redis；后者不证明所有worker在线。

默认DEMO_MODE=true保留演示账号。正式部署设置DEMO_MODE=false及至少32字符的私有JWT_SECRET，禁用演示账号登录和自动初始化。首次管理员在后端目录交互创建，密码不回显：

    .\.venv\Scripts\python.exe -m app.create_user --email admin@example.com --tenant MyCompany

前端支持普通账号登录；已有有效会话不会每次刷新都重新登录演示账号。JWT和角色管理属于当前应用权限基础，不包含SSO或完整企业用户管理后台。
