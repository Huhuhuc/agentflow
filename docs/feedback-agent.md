# 反馈处理 Agent

## 实现内容

新增的工作台支持提交反馈、查询版本资料与相似反馈、查看工具调用轨迹、审核工单草稿、人工确认保存工单，以及离线评估。前端默认打开此工作台，旧工作流页面仍保留。

真实模型通过 OpenAI-compatible function calling 选择工具。执行器将工具结果回传给模型，直到得到结构化最终结果或达到限制。Mock 使用确定性策略模拟这套协议，不代表模型推理效果。三个工具分别是 `search_release_notes`、`find_similar_feedback`、`draft_feedback_ticket`。草稿工具没有保存工单的权限，工单只能通过已鉴权的人工确认接口保存。

## 启动与演示

按 README 的方式启动前后端。已有数据库在启动时创建新增表，不删除旧工作流和记录。

1. 进入“反馈处理 Agent”，保持 Mock 模式，提交“2.4 更新后火球技能伤害异常，请核实倍率”。
2. 查看运行记录，确认工具检索和草稿生成步骤；打开来源和运行快照。
3. 查看待确认草稿，点击“人工确认并保存工单”。刷新后工单仍然保留。重复确认返回同一工单。
4. 将版本改为 `9.9` 再提交，展示没有对应资料时请求补充信息，不创建草稿。
5. 提交描述相似的新反馈，查看 `find_similar_feedback` 的结果；相似反馈不是已确认的重复问题。
6. 切换“效果评估”，运行 Mock 评估，查看逐项结果和限制说明。

## 真实模型配置

将以下配置放入 `backend/.env`（本地）或通过 Compose 根目录 `.env` 传入 API 容器。不要提交密钥。

```dotenv
OPENAI_API_KEY=your-key
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini
```

重启后端，在工作台选择“真实模型”。该模式会发生真实模型调用与相应费用；没有密钥会拒绝请求，不会静默转成 Mock。服务必须兼容 Chat Completions 的 `tools` / `tool_calls` 协议。`LLM_MODE` 控制旧工作流节点，新 Agent 每次运行显式选择模式。

## 执行与持久化

- 单次运行最多 6 个模型步骤、6 次工具调用、每轮最多 3 个工具、12000 Token 的累计上限，以及 120 秒执行预算；Token 使用在响应后核算，超过后停止后续步骤。
- 每次模型请求有超时，最多 2 次重试，Agent 的重试等待最长 2 秒。按剩余执行预算缩短请求超时。预算检查无法终止已经发生的外部调用或保证供应商计费上限。
- 保存输入、系统提示词、工具定义、模型名、知识快照和限制；保存模型/工具步骤的参数、结果、错误、耗时、尝试次数与 Token。
- 工具参数用 Pydantic 校验，不允许额外字段；执行器拒绝未知工具、版本不一致和未检索的证据引用。
- 所有反馈、运行、相似反馈检索和确认工单按当前用户所属租户过滤；唯一 `run_id` 保证确认幂等。
- 新 Agent 使用本地后台任务，单步写入数据库并由前端轮询。进程重启后的自动恢复和耐久任务队列尚未实现，不能宣称可靠分布式执行。
- 旧 DAG 执行新增图快照：优先取最新发布版本，没有发布版本时明确保存当前草稿快照；修改草稿不改变已创建运行的图。旧历史运行没有快照时兼容旧行为。

## 评估

```powershell
cd backend
.\.venv\Scripts\python.exe -m app.agent_evaluation --mode mock --output ..\docs\feedback-agent-evaluation.json
```

真实评估需要配置密钥并显式使用 `--mode openai`。浏览器评估接口仅支持 Mock，不会产生模型费用。评估在隔离内存数据库中运行，不写入用户业务记录或工单。

数据集位于 `backend/evaluation/feedback_cases.json`，有 8 个合成标注样本，包含伤害、闪退、匹配、描述模糊、缺失版本资料、指令文本和相似反馈。比较规则基线、单次响应、工具调用 Agent 的分类、路由、安全完成、证据 ID 检查、工具覆盖、耗时和 Token。规则及单次响应不提供检索，Agent 提供工具，比较并非资源一致的算法实验。Mock 单次响应复用规则分类；结果只能证明流程与约束，不证明真实模型效果或统计显著性。

来源 ID 的合法性检查不等于文本的语义支持度；人工审核仍需检查建议是否有证据。Mock Token 为 0，费用为 `null`，不填造价格或业务指标。

实际联网调用需要额外验收。本次自动测试通过拦截 HTTP 响应验证 function calling 协议、工具观察结果回传、参数/证据校验、租户隔离、失败日志、预算停止与确认幂等性。没有声称完成生产部署、向量检索、多 Agent 协作、真实业务指标或外部工单连接。
